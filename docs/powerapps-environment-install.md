# Install Guide: Deploy this PCF Control to a Power Apps Environment

## Who this guide is for

This guide is for first-time deployment to a Dataverse/Power Apps environment. It covers two audiences — most sections apply to both.

- **Developers** — building, iterating, and pushing the control to a dev environment via `pac pcf push`
- **Power Platform Admins** — deploying to test/production via managed solution import in Maker Portal

> **For Admins:** You do not need Node.js, npm, or `pac` CLI for production deployments. Jump to [Section 7 — Recommended production path](#7-recommended-production-path) if a developer has already exported the managed solution for you.

> **For Developers:** Follow every section in order. The Quick Start at the bottom is your fastest path once you've done this once.

## Tooling method used in this project (exact)

Use this exact setup:

- **Shell**: PowerShell
- **Build tool**: npm (`npm install`, `npm run build`)
- **Deployment tool**: Power Platform CLI (`pac`)

For developer installation, **do not use ZIP upload**. Use `pac pcf push`.

ZIP/managed solution import is for release promotion (test/prod), not quick dev install.

## What files you need to move (important)

For `pac pcf push`, you **do not manually move files** to Power Apps.

The CLI reads your local project and publishes it for you, primarily from:

- `ActivityTimelineControl/ControlManifest.Input.xml` (control metadata/inputs)
- `ActivityTimelineControl/` source files (TypeScript/CSS/resources)
- Build output generated by `npm run build` (under `out/`)

In short:

- Run `npm run build`
- Run `pac pcf push --publisher-prefix <yourPrefix>`
- No drag/drop or manual file copy into environment required

## 1. Prerequisites

**All users:**
- Access to a Power Apps environment (example URL: `https://<org>.crm.dynamics.com`)
- Permissions to customize tables/forms (System Customizer or System Administrator role)

**Developers only:**
- Power Platform CLI (`pac`) installed — [install guide](https://learn.microsoft.com/en-us/power-platform/developer/cli/introduction)
- Node.js (v16+) and npm installed

> **For Admins:** You do not need Node.js or `pac` CLI unless you are doing dev pushes yourself.

Quick checks (developers):

```powershell
node -v
npm -v
pac help
```

> Note: `pac --version` is not a valid command on this CLI build. Use `pac help` to confirm install.

## 2. Build the control

From repository root:

```powershell
npm install
npm run build
npm test
```

> If you already built successfully and code has not changed, you can skip re-running build.

## 3. Authenticate to your environment

```powershell
pac auth create --url "https://<your-org>.crm.dynamics.com"
pac auth list
```

If multiple profiles exist, select one:

```powershell
pac auth select --index 1
```

## 4. Push control to environment (dev/test)

Use your solution publisher prefix:

```powershell
pac pcf push --publisher-prefix <yourPrefix>
```

Example:

```powershell
pac pcf push --publisher-prefix contoso
```

## 5. Add control to a form in Maker Portal

1. Go to `https://make.powerapps.com`
2. Select the same environment used in `pac auth`
3. Open the target table
4. Open the form you want to customize
5. Select the target field (or component host location)
6. Add component/control and choose this PCF control
7. Bind inputs:
   - `recordId`
   - `entityName`
8. Save and publish

## 6. Validate installation

- Open a record of the target table
- Confirm control loads without errors
- Verify data behavior for your record context
- If testing in harness first, remember blank `recordId`/`entityName` can show empty state

## 7. Recommended production path

For production rollout, avoid direct `pac pcf push` and deploy via solution lifecycle:

1. Add control to an unmanaged solution in dev
2. Export as managed solution
3. Import managed solution into test/prod
4. Validate and publish

## 8. Troubleshooting

### `pac` not found

- Reopen VS Code/terminal after installation
- Re-run `pac help`

### Auth fails

- Verify URL is correct environment URL
- Confirm account has permissions
- Check selected profile with `pac auth list`

### Push fails with prefix error

- Use the publisher prefix from your Dataverse solution publisher

### Control not visible in form designer

- Confirm `pac pcf push` succeeded
- Refresh browser and re-open form designer
- Ensure you are in the same environment

### Control on form but no data

- Confirm field/property bindings include `recordId` and `entityName`
- Verify there is related data for that record

## Quick Start (copy/paste exact sequence)

Run this from repo root in PowerShell:

```powershell
node -v
npm -v
pac help
npm run build
pac auth create --url "https://<your-org>.crm.dynamics.com"
pac auth list
pac pcf push --publisher-prefix <yourPrefix>
```

Then in Maker Portal:

1. Add control to form
2. Bind `recordId` and `entityName`
3. Save + Publish
